# Agent Note: 压缩检查点携带被遮蔽的 todo 列表

Status: implemented

[English](2026-08-14-compaction-checkpoint-todo-stub.md) | 中文

## 问题

`todo/write` 是仅日志的 UI 状态：该事件不会派生模型消息，因此模型对自身任务列表的认知完全依赖表层上还留存的 `todo_write` 工具结果。压缩会用有损摘要替换较早的表层范围，而摘要是否保留进度图全凭运气。任务中途压缩之后，模型经常丢失列表——这正是进度状态保留研究列为最高优先级上下文主权缺口的那类失败：导航状态廉价、确定，不应依赖摘要器的善意。

## 决策

**替换检查点追加的是确定性存根，而非摘要产物。** 当最新的 `todo/write` 快照被压缩范围遮蔽时，`compactSurfaceRegion` 会在 `</compacted-summary>` 闭标签之后追加一个 `<todo-state>` 文本块：每项一行 `- [<status>] <content>`，状态词沿用工具自身的词汇。该块搭载同一条已记录的替换 user 消息，因此「模型可见 ⟺ 已记录」按构造成立；回放派生不变。

**遮蔽判定是精确的，不是启发式。** 一次 `todo/write` 追加在其工具调用与结果之间，而平衡配对保证截止点永不劈开这对事件。该写入被遮蔽，当且仅当其 seq 不超过最后一个被遮蔽的表层节点；高于截止点的写入仍保留在近期尾部，不附加任何内容，因此没有会话为不需要的存根付费。空快照同样不附加。

**不提供配置项。** 在唯一的丢失点注入智能体自己的进度图，是检查点格式的正确性属性而非部署选择；没有 todo 列表的会话不受影响。

## 考虑过的替代方案

- **在摘要指令中要求保留列表** —— 已否决：存根必须是确定性的；摘要行可能丢失、重排或改写状态词，而失败恰好在列表最重要时回来。
- **每个请求都注入列表** —— 已否决：会逐轮复制近期尾部仍可见的 `todo_write` 结果；存根只在丢失点需要。
- **压缩后追加由 `todo/write` 派生的模型消息或 steering 通知** —— 已否决：`todo/write` 按契约仅限日志，而替换检查点是既有的、缓存对齐的、唯一穿过该边界的持久面。

## 后果

检查点仅在列表本会丢失时增长出当前列表的行数；缩减校验为存根计价，因为该块在估算之前就是检查点消息的一部分。`<todo-state>` 标签由此成为稳定模型可见文本，由 headless 压缩 e2e 与包测试中的回放等值不变量钉住。带被遮蔽写入的无密钥组装快照仍延期：录制它需要活提供方转录，而在没有密钥验证的情况下向已录制的溢出夹具手工插入工具轮次，有夹具手术风险。
